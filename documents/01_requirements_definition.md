# 要件定義書（01_requirements_definition.md）

## 1. プロジェクト概要
本システム「AI Investment Firm（マルチAIエージェントによる仮想投資会社）」は、米国株式市場（S&P500主要銘柄および優良ETF）を対象としたペーパートレード（仮想売買）シミュレーションシステムである。
追加課金ゼロ（Pythonオープンソースライブラリ、Gemini API無料枠、GitHub Actions無料枠、GitHub Pages無料枠）で完全自律運用を実現し、日本時間の毎朝9:00に自動稼働してスクリーニング・AIエージェント経営会議・仮想約定・朝刊Webダッシュボード生成を行う。

---

## 2. 業務要件（ビジネスゴールと運用フロー）

### 2.1 背景と目的
- 少額資金（初期資金 `$330.0` ≒ 約50,000円、月次積立 `+$100.0` ≒ 約15,000円）から始める米国株長期・分散投資をシミュレーションする。
- 膨大な市場データから有望銘柄を抽出する一次スクリーニングをPythonの定量計算で行い、最終的なファンダメンタルズ（ニュース）評価・テクニカル評価・ポートフォリオ意思決定をマルチAIエージェントの合議制で行うことで、APIコストを最小化しつつ根拠の明確な投資判断を毎朝提供する。
- ユーザーがSBI証券等のネット証券で実際の取引を行う際の判断材料および具体的な手動注文ガイドを朝刊ダッシュボード（HTML）として配信する。

### 2.2 日次業務フロー
1. **営業日判定（休場日スキップ）**: 米国市場の最新取引日を確認し、土日・祝日で前日終値が更新されていない場合は処理をスキップする（`--force` 指定時は強制実行）。
2. **月次積立判定**: 月初の初回実行時に限り、仮想口座の現金残高へ `+$100.0` を自動入金する。
3. **第1段階：一次スクリーニング（AI不使用）**: 厳選50銘柄（S&P500主要11セクター代表45社＋低価格優良ETF 5銘柄）の株価・出来高データを取得し、現金残高で購入可能な銘柄からテクニカルスコア上位6銘柄を選出する。
4. **第2段階：マルチAIエージェント経営会議（最小APIコール）**: 上位6銘柄と現在保有銘柄の指標・直近ニュースを統合し、情報収集担当・テクニカル分析担当・ファンドマネージャーの3役による議論と最終意思決定（`BUY` / `SELL` / `HOLD`）を構造化JSONで取得する。
5. **執行・経理処理（物理バリデーション＆記帳）**: 執行・経理担当モジュールが現金残高・1株単位整数条件・1銘柄35%上限ルール（初期免除特例あり）・保有株数上限を検証し、違反時は安全に `HOLD` へフォールバックさせた上で確定終値にて仮想約定・記帳を行う。
6. **レポート・朝刊ダッシュボード出力**: 日次Markdownレポート（`reports/YYYY-MM-DD.md`）およびGitHub Pages用Webダッシュボード（`docs/index.html`）を生成し、Gitリポジトリへ自動コミット＆プッシュする。

| FR-09 | CI/CD日次自動実行機能 | GitHub Actionsにより毎朝9:00（JST）に自動実行（`--proposal-only` 方針提案モード）し、更新ファイルをリポジトリへ自動コミット＆プッシュする。 | `.github/workflows/daily_meeting.yml` |

## 4. 非機能要件

1. **コスト制約（完全無料運用）**
   - 有料APIや有料データベースは一切使用しない。
   - Gemini APIは `gemini-2.5-flash` を使用し、1回の実行につきAPIコールは最大1回に抑制する。
2. **信頼性・耐障害性**
   - `yfinance` の `MultiIndex` カラム仕様変更や一部ティッカーの通信失敗・ニュース構造差異が発生してもシステム全体を停止させず、該当ティッカーのスキップまたはフォールバックにより完走させる。
   - `GEMINI_API_KEY` 未設定時やAPI通信例外発生時は、自動的に安全な `HOLD`（現金温存）判断へフォールバックする。
3. **セキュリティ・脆弱性対策**
   - APIキーはローカルでは `.env`、GitHub Actionsでは `GitHub Secrets` から環境変数経由で読み込み、ソースコードやGit履歴に一切含めない。
   - ローカルWebサーバー（`server.py`）は `127.0.0.1` バインドとし、`Origin` ヘッダー検証（外部悪意サイトからのCSRF/CORS遮断）、リクエストボディ上限（64KB）、ティッカー正規表現検証、CSV数式インジェクション無害化（`_sanitize_csv_field`）、およびHTML/DOM XSSエスケープ（`html.escape` / `escapeHtmlJs`）を徹底する。
4. **保守性・テスト容易性**
   - Python 3.11以上で動作し、外部通信（`yfinance`, `google-genai`）をモック化した `pytest` 自動テストスイート（単体・結合・シナリオ計19テスト）により全ロジックを検証可能とする。

## 5. 投資ルール制約一覧（厳守仕様）

| ルール項目 | 制約内容 | 検証タイミング |
| :--- | :--- | :--- |
| 初期資金 | 初回起動時 `$330.0`（初月は `+$100.0` の積立加算を行わない） | 起動時（`portfolio.json` 初期化時） |
| 月次積立 | 実行年月 `YYYY-MM` が `last_deposit_month` と異なる場合のみ `+$100.0` 加算 | 日次処理開始時 |
| 取引種類 | 現物取引のみ（信用取引・空売り・レバレッジ取引は禁止） | 執行バリデーション時 |
| 売買単位 | 1株単位の正の整数（`int`, `shares >= 1`）のみ。端株・小数株は禁止 | スクリーニング時・執行バリデーション時 |
| 買付余力制限 | `購入株数 × 現在株価 <= 現在の現金残高` であること | スクリーニング時・執行バリデーション時 |
| 売却数量制限 | 保有中の銘柄であり、かつ `売却株数 <= 現在保有株数` であること | 執行バリデーション時 |
| セクター分散 | 既存保有銘柄と同一セクターへの集中を避け、異なるセクターへの分散を優先する | スクリーニング加点・AI会議プロンプト |
| 1銘柄35%上限ロック | 購入後の当該銘柄評価額が `総資産 × 35%` を超える追加購入をブロックする | 執行バリデーション時 |
| 初期デッドロック回避特例 | **総資産が `$1,000.0` 未満** かつ **未保有銘柄** を **新規に1株だけ（`shares == 1`）** 購入する場合に限り、現金残高の範囲内であれば35%上限制限を免除する | 執行バリデーション時 |
